# Readiness evidence lifecycle and reconciliation scope

This audit was completed before implementation. Existing production selection and validation policies do not need a change.

The selector `reports/current-publication-validation/current-evidence.json` explicitly names exactly one semantic successor and one validation successor by project-local path and SHA-256. It also authenticates both fixed original predecessors. It does not discover files by newest timestamp or search external audit directories. A malformed present selector fails closed; absent selection uses the original historical records. Explicit selection resolves precedence, but it grants no execution or semantic success.

Selection verifies path containment, regular files, symlink exclusion, record hashes, predecessor identities and optional portable semantic custody. The later semantic and validation validators independently require the exact current HEAD, input membership and bytes, command/tool identity, completion and output custody. No future Git-SHA checkpoint is accepted by this task.

The current selector names the bounded three-term reports. That validation ledger binds 276 inputs; the current required set has 316. Forty members are absent and fourteen common identities differ. Its seven commands omit the separately required full unit-discovery and full repository roles. The semantic report binds two old implementation/test files, omits three custody dependencies, and has twenty-nine command records bound to the former input set. None of the six semantic/product pins changed.

`make check` and `make compile` execute validations but do not issue or select native publication ledgers. The prior external recorder captured both exact commands, their completed real return codes, timestamps, before/after HEAD and all 316 inputs, zero drift, executable identity, complete logs and its own exact source bytes. The captured command set remains byte-applicable; its record format and external paths are not directly accepted as native readiness records.

The established report-local `three-term-20261028/record_commands.py` executes named commands and records native input/tool/output custody, then creates an additive ledger. It deliberately excludes the full gates and cannot overwrite occupied receipts. The new scoped report workflow follows this pattern, retaining two exact external executions unchanged and deriving explicit native custody views. Derived fields must be justified from original capture facts, with no claimed new execution or extra historical measurement. Import requires exact authorized source receipt/log/recorder hashes, logical role, original repository and checkpoint, command identity, complete current input equality and completion. Original source files are copied without alteration. No PASS is inferred from text alone.

The exact missing `python -B -m unittest discover -s tests` command must execute. The five readiness Python commands also need actual native execution because their canonical child arguments differ from the strict required identities. An optional old scoped-authentication record need not be replayed as a required role. The eight required roles remain unchanged.

Semantic issuance is separate. `tools/current_semantic_validation.py --output NEW_REPORT` generates actual new tickets, captures, envelopes, graph/command bindings and summaries. Historical reconciliation is explicitly retired and cannot freshen earlier execution metadata. The twenty-seven exact semantic slots plus compiler/version commands are distinct from normalized canonical smoke/ELK/HermiT checks. Missing SKOS imports and profile/declaration failures remain independent publication backlog; a newly completed FAIL must never be presented as PASS.

The new issuer and its tests are colocated in this established reporting workstream, as scoped evidence-issuance artifacts. Every issued command binds them as result/provenance artifacts. No shared production validator, `tools/`, `tests/`, configuration, workbook or product is changed. The 316 whole-suite input set must remain exact; any movement invalidates reuse and stops issuance. Existing readiness/evidence suites and the report-local issuer tests must pass before selection.

All prior semantic/validation reports, logs, outcomes, six pins, 49 governed SOSA-2023 paths, 27 retained RDF objects and 61 exclusions remain protected. The current selector is the only existing report eligible to change, and only after applicable current records authenticate. This document is an implementation rationale, not a readiness result, issued execution receipt, semantic decision, or staging plan.
