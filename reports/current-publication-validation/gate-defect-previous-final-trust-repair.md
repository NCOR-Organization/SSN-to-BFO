3. **Pre-execution ticket.** Every fresh governed reasoner run now has a canonical JSON ticket created with `O_CREAT|O_EXCL` before Java starts. It contains a UUID invocation ID, 256-bit `secrets` nonce, reconstructed slot and role/analysis/side/phase/corpus/query identity, exact graph and query paths/byte hashes, command, wrapper hash, governed input hashes and a provenance timestamp. The ticket SHA-256 is over deterministic serialization. Required slots come from governed files and configuration, never from a summary.

4. **Ticket-consuming helper and envelope.** The wrapper independently reconstructs the expected slot, hashes the actual graph/query files immediately before launching Java, checks command/mode and wrapper identity, and refuses mismatches. It alone captures subprocess stdout/stderr bytes and writes create-once channel files, a challenge-bearing capture with begin/end markers and base64 bytes, and a create-once result envelope. The envelope binds the ticket hash, invocation ID/nonce, slot and execution identity, graph/query hashes, command/helper, exit state, stdout/stderr hashes and byte counts, and capture hash. `javac` and `java -version` remain toolchain setup with their existing command/input/output records; they are not reasoner evidence slots.

5. **Stdout provenance boundary.** Fresh validation checks reconstructed plan → selected slot → ticket → wrapper capture/envelope → exact retained bytes → derived status/classification → stored summary. Refreshing summary, raw-result or manifest hashes cannot change the ticket/capture/envelope relation. This prevents post-hoc rebinding while those create-once artifacts remain intact. It is local evidence custody, not a signature or nonrepudiation proof against an actor able to rewrite every local file and validator code; external append-only or signed custody would be needed for that stronger threat model.

6. **Raw-output adversarial matrix.** The [focused log](current-publication-validation/final-trust-focused.log) includes failing substitutions for A cross-example, B hierarchy-to-example, C source-only-to-aligned, D aligned-to-source-only, E different query and same query ID with different query bytes, F different input graph, G second invocation of the same slot, H foreign stdout after refreshing mutable summary/raw/manifest/ledger fields, I foreign envelope plus stdout, J summary-only nonce edit and K nonce reuse. Honest blocked and successful synthetic subprocess outputs pass the same custody validator. Changed graph/query bytes prevent wrapper launch. The tests use disposable fixture outputs through the real wrapper code; they do not assert a new successful production HermiT run.

7. **Same-slot reexecution.** A second attempt gets a distinct ticket, invocation ID and nonce even with identical slot, command and inputs. Each attempt is retained separately; a create-once selected-invocations record names the one used by the publication report. Replacing its stdout with the second attempt or switching only the mutable report selection fails. A separately verified second attempt is valid evidence only when explicitly selected under its own ID.

8. **Human decision record.** Every new final assessment requires a project-specific `human_decision_record` path and SHA-256. Schema version 1 binds a UUID decision ID; exact term, `final` state, outcome, rationale, packet question and explicit response; reviewer and timezone-aware time; evidence references; RowIDs and current formal predicates/targets or deliberate absence; current source, target, workbook, scope and source-query hashes; formal coverage; and hashed pre-decision assessment and complete per-term packet snapshots. The validator reconstructs the packet with the report generator's own extraction path, including target facts, chains and pinned-track comparison, and checks exact equality. This records an explicit decision artifact; software cannot prove that a person actually reasoned about it.

9. **Historical baseline.** Exactly the prior twelve documentary finals are pinned in [the baseline](../config/current-ssn-sosa-historical-finals.json), whose entire SHA-256 is pinned in the validator. Each exception binds source IRI, outcome, historical evidence/basis and the complete canonical assessment-record hash. These ten formal-adopted and two no-direct outcomes remain valid unchanged; no historical recommendation or workbook row automatically expands the exception. A changed historical final or persisted reopening must go through an unresolved packet and new decision. A transient reopen followed by byte-exact restoration is unobservable from mutable local current state and would need external append-only custody to detect.

10. **Finality transitions.** Validation runs before queue/rationale generation. A final state whose complete record is not an unchanged historical exception must match its own hashed decision, current workbook and evidence state. It must cite an unresolved pre-decision assessment and a complete matching packet. A stale, missing, wrong-term, wrong-outcome or truncated packet/decision fails closed.
